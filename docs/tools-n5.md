# 正式工具集设计方案（N5）

状态：已实现（2026-11-02）。第 4 节的决策全部选 A；实现记录见第 6 节。对应 [roadmap](roadmap.md) 第 2 节 N5，建立在 [agent loop](agent-loop.md) 的 N1–N4、N6 之上。

## 1. 目标

把 Zanbot 从"只能读写笔记目录"扩展到能处理日常的个人事务：读写指定目录里的文件、在你同意时执行命令、读网页、主动记住和忘记事情。

非目标：沙箱隔离（S 阶段）、MCP（N8）、ChatGPT 下使用工具（N7）、可配置的持久权限规则（S 阶段）。

## 2. 现有基础（不用重做）

- **注册表**：`Tool(name, description, input_schema, side_effect, run)`；新增一个工具 = 一个函数 + 一个声明。
- **权限**：`side_effect != "none"` 的调用先问 y / n / a；plain 模式一律拒绝，并告诉模型原因。
- **副作用记录**：失败或取消的轮次里已执行的副作用，会在下一轮告诉模型。
- **输出处理**：结果包在 `<tool_output>` 里，超过 10,000 字符截断，并提示模型用 offset/limit 分段读。
- **显示**：每次调用在终端显示一行 `→` / `✓` / `✗`。

## 3. 工具清单（草案）

| 工具 | side_effect | 说明 |
|---|---|---|
| `list_dir` | none | 已有；范围从笔记目录扩大到工作区（见 E1） |
| `read_file` | none | 读文本文件，支持 `offset` / `limit`（按行）；二进制文件拒绝 |
| `write_file` | local | 新建或整体覆盖文件 |
| `edit_file` | local | 把文件里唯一出现的一段文字替换成新文字（见 E5） |
| `run_shell` | external | 在工作区里执行一条命令（见 E2） |
| `web_fetch` | external | 读取一个网页的正文（见 E3） |
| `remember` / `forget` | 见 E4 | 让模型直接管理长期记忆 |

## 4. 决策

每项给出选项和推荐。2026-11-02 拍板，全部采用推荐方案 A。

### E1 文件工具能访问哪里？

| 选项 | 说明 | 代价 |
|---|---|---|
| **A（推荐）** 工作区 | 启动时用 `--workspace <目录>` 指定；不指定就是笔记目录。所有文件工具都限制在工作区内，路径越界一律拒绝 | 要多记一个参数；但边界清楚，面试好讲 |
| B 启动时的当前目录 | 在哪个目录运行 Zanbot，就能访问哪里 | 不用配置；但容易在家目录里启动，范围过大 |
| C 不限制，每次都问 | 任何路径都行，读写都要许可 | 读文件也要确认，很烦；安全全靠用户逐次判断 |

决定：**A**。

### E2 `run_shell` 本期做不做、怎么做？

| 选项 | 说明 | 代价 |
|---|---|---|
| **A（推荐）** 做，但每次都问 | 每条命令都要确认，**不提供 `a`（总是允许）**；工作目录固定为工作区；30 秒超时后结束进程；Windows 用 PowerShell | 一次一问；但这是最危险的工具，值得 |
| B 做，和其他工具一样可选 `a` | 体验更顺 | 一次 `a` 之后，模型可以执行任何命令 |
| C 不做，留到 S 阶段有沙箱再说 | 最安全 | 少了最有用的能力之一 |

决定：**A**。

### E3 `web_fetch` 怎么做？

| 选项 | 说明 | 代价 |
|---|---|---|
| **A（推荐）** 本地实现，每次问 | 只允许 http(s) GET；拒绝 localhost 和内网地址；HTML 转成纯文本；结果按不可信数据处理。归为 `external`，需要许可（可选 `a`） | 每个新会话第一次要确认；能防"网页里藏指令 → 把你的数据塞进 URL 发出去"这类攻击 |
| B 本地实现，不问 | 当作只读工具 | 方便；但 URL 本身就能把数据带出去，被注入后风险最大 |
| C 用 Anthropic 服务端的 web_fetch / web_search | 不用自己写抓取；还能搜索 | 只能用于 Anthropic；流式解析要支持服务端工具块和 `pause_turn`；行为不在本地掌控 |

决定：**A**。

### E4 记忆变成工具？

现在记忆由后台步骤自动抽取，模型自己不能存或删（system prompt 里明确这么说）。

| 选项 | 说明 | 代价 |
|---|---|---|
| **A（推荐）** `remember` 不问，`forget` 要问 | `remember` 和后台自动保存一样不用确认，会显示 `✓ Remembered #id`，可以 `/forget` 撤销；`forget` 会删掉数据，要确认。同步更新 system prompt 里的记忆说明 | 用户说"记住这个"时能立刻生效；要改记忆说明和相关测试 |
| B 都不做 | 保持现状，靠后台抽取 | 最简单；"记住这个"要等后台抽取，且可能没被抽到 |
| C 都要问 | 最保守 | 和后台自动保存不问的做法不一致 |

决定：**A**。

### E5 写文件怎么设计？

| 选项 | 说明 | 代价 |
|---|---|---|
| **A（推荐）** `write_file` + `edit_file`，去掉 `write_note` | 新建或覆盖用 `write_file`；改一小段用 `edit_file`（要替换的原文必须在文件里只出现一次）。确认时显示改动摘要 | 两个工具；改大文件时不用整个重写，省 token，也更不容易改坏 |
| B 只有 `write_file` | 每次整体覆盖 | 简单；改大文件很费 token，也容易丢内容 |
| C 保留 `write_note`（只追加），再加 `write_file` | 追加最安全 | 工具重叠，模型容易选错 |

决定：**A**。

### E6 工具执行多久算超时？

| 选项 | 说明 | 代价 |
|---|---|---|
| **A（推荐）** `run_shell` 30 秒，`web_fetch` 15 秒，文件工具不设 | 超时后结束并把已有输出返回给模型 | 长命令（如安装依赖）会被打断 |
| B 统一 60 秒 | 简单 | Ctrl+C 要等工具结束（D2 是协作式取消），最多卡 60 秒 |

决定：**A**。

## 5. 测试计划

- **路径**：`..`、绝对路径、符号链接都不能跳出工作区；读二进制文件被拒绝；`offset` / `limit` 分段读取。
- **edit_file**：原文不存在、出现多次时报错，不改文件；成功时只改一处。
- **run_shell**：超时后进程被结束；输出截断；`a` 对它无效；plain 模式拒绝。
- **web_fetch**：拒绝 `file://`、localhost、内网 IP（含跳转之后的地址）；HTML 转文本；网页里的"忽略之前的指令"按数据处理。
- **记忆工具**：`remember` 后出现在 `/memory` 里，可以 `/forget`；`forget` 需要确认。
- **手动验证**：真实 API 下各跑一个典型任务。

## 6. 实现记录

分四次提交：文件工具与工作区、`run_shell`、`web_fetch`、记忆工具。

- **权限分级**：`Tool` 新增 `permission`：`none`（不问）、`ask`（问，可选 `a`）、`ask_each_time`（每次问，不提供 `a`）。默认值由 `side_effect` 推出。会话层也做了兜底：即使前端返回 `a`，对 `ask_each_time` 的工具也按拒绝处理，不会记住。
- **副作用和权限分开**：`remember` 有副作用（轮次失败时会告诉模型），但按 E4 不需要确认，所以循环改用 `needs_permission` 决定是否问，用 `has_side_effect` 决定是否记录。
- **确认时显示人能看懂的说明**：工具可以提供 `describe`；`forget` 的确认会显示 `memory #12: 记忆原文`，而不是 `{"id": 12}`。
- **文件工具**：`write_note` 已删除。`read_file` 默认 400 行，可用 `offset` / `limit`；超过 5 MB 或前 8 KB 有空字节（二进制）就拒绝。`write_file` / `edit_file` 按原样写入，不转换换行符，Windows 的 `\r\n` 会保留。工作区不存在时，`--workspace` 报错退出；默认的笔记目录会自动创建。
- **`run_shell`**：Windows 下用 `powershell -NoProfile -NonInteractive`，并先把输出编码设成 UTF-8；没有标准输入；30 秒后用 `taskkill /T` 结束整个进程树。退出码非 0 时标为错误，但输出照样返回给模型。
- **`web_fetch`**：不自动跟随跳转，而是每一跳都先检查地址；只要域名解析出的地址里有一个不是公网地址，就拒绝（含 IPv4 映射的 IPv6）。只读文本类内容；字符集优先用响应头，其次是网页里的 `<meta charset>`，最后用 UTF-8（requests 对没声明字符集的文本默认用 ISO-8859-1，中文会乱码）。
  - 已知局限：先解析检查、再由 requests 连接，中间如果 DNS 结果变了（DNS rebinding），检查会被绕过。彻底解决要把连接绑定到检查过的 IP，留到 S 阶段。
- **记忆工具**：只在记忆开启时提供。有记忆工具时，system prompt 换用 `MEMORY_GUIDE_TOOLS`（用户明确要求时才用工具，工具成功后才说"记住了"），记忆列表里带上 `#ID`，供 `forget` 使用。`remember` 复用原来的密钥检测；它只认 `sk-…` 和长 token 这类字符串，像"密码是 hunter2"这种自然语言的密码拦不住，这是记忆模块原有的局限。
- **真实 API 验证**（临时工作区和临时记忆库，脚本自动回答 y）：改写 todo.md 时先 `read_file` 再 `edit_file`；数文件时 `run_shell` 的确认没有 `a` 选项；`web_fetch` 正确总结了 example.com；"记住下周三交报告"直接 `remember`，并把"下周三"换算成了具体日期；"忘掉刚才那条"时 `forget` 先确认，确认文字显示了记忆原文。
- 符号链接越界的测试在这台 Windows 上被跳过（创建链接需要额外权限）；防护靠的是 `resolve()` 跟随链接后再检查，和其他越界测试走的是同一段代码。
