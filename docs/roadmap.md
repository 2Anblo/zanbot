# Zanbot 路线图

状态：草稿（2026-10-24，2026-11-02 更新）。长期记忆 P1、P2，CLI 体验 C1–C3，工具调用 N1–N7 已完成（N8 MCP 未做）；下一步见第 1 节的阶段（S 安全、K 上下文、E 评测）。

## 1. 最终形态

**一个跑在本地、记得你、能替你动手的个人 agent。**

| 能力 | 含义 | 现状 |
|---|---|---|
| 对话 | 多轮、流式、可取消，多个模型 provider | ✅ Anthropic + ChatGPT 计划登录 |
| 记得你 | 自动抽取长期记忆，可查看、撤销 | ✅ P1/P2；检索精度（P3）待做 |
| 能动手 | 模型调工具 → 执行 → 结果喂回 → 循环 | ✅ N1–N6：文件、命令、网页、记忆工具 |
| 守规矩 | 有副作用的工具先问你；外部内容不能当指令 | 🟡 基础版：y/n/a 确认 + 工具输出标注为数据；S 阶段补全 |
| 不爆上下文 | 长对话自动压缩，记忆按相关性检索 | ❌ |
| 可衡量 | 记忆抽取、工具调用各有一个小评测集，能跑出数字 | ❌ |
| 天天在用 | 至少一个每天真用的场景（例如早间简报、整理笔记建待办） | ❌ |

非目标：多用户、云端部署、GUI、跨设备同步。保持一个人、一台机器、一个终端。

### 阶段

1. **N：Agent loop + 工具**（下一阶段，见第 2 节）
2. **S：安全与权限**——权限策略可配置，工具结果标记为不可信数据，审计日志
3. **K：上下文管理**——历史摘要压缩、记忆按相关性召回（即记忆设计里的 P3）
4. **E：评测**——记忆抽取 ~30 条用例、工具选择 ~30 条用例，可在 CI 里跑
5. **D：日常场景**——定时任务（早间简报）、个人笔记/待办工具

每个阶段沿用现有做法：先在 `docs/` 写设计，再在 feature 分支实现，最后合并。

## 2. 下一阶段：Agent loop + 工具（N）

### 现状约束（来自代码）

- `agent.run_turn` 只接受 text 块；遇到别的块，或不认识的 `stop_reason`（包括 `tool_use`），直接报错。
- `streaming.read_message` 只拼接 text delta，不处理 `tool_use` 块和 `input_json_delta`。
- `chatgpt.create_message` 只读 `output_text`，没有 function call。
- `ChatSession` 的事件只有文本相关的几种（`ReplyStarted`、`TextDelta`、`ReplyFinished`……），前端无法展示工具调用，也无法向用户请求许可。
- 已有原则：**成功后才写入历史**；取消的轮次不保存、不抽取记忆。循环里要继续守住这一条。

### 拆分

| 步骤 | 内容 | 完成标准 |
|---|---|---|
| N1 | 流式解析支持 `tool_use` 块（Anthropic） | `read_message` 返回 text + tool_use 混合的 content；测试覆盖分片的 JSON 输入 |
| N2 | `agent.py` 改成循环：调用 → 执行工具 → 追加 `tool_result` → 再调用，直到 `end_turn` | 有最大步数（如 10）；任一步失败则整轮不写入历史；Ctrl+C 能在任一步中止 |
| N3 | 工具注册表：名字、描述、JSON schema、`side_effect` 等级（none / local / external） | 新增一个工具只需写一个函数 + 一个声明 |
| N4 | 权限：`side_effect != none` 的调用先发 `PermissionRequested` 事件，前端问 y/n | 拒绝也作为 `tool_result` 回给模型；`--plain` 模式默认拒绝 |
| N5 | 首批工具：`read_file`、`list_dir`、`write_file`（需许可）、`run_shell`（需许可）、`web_fetch`、`remember`/`forget`（把现有记忆变成工具） | 每个工具有单元测试；路径限制在用户指定的工作目录 |
| N6 | 会话事件：`ToolCallStarted`、`ToolCallFinished`，CLI 显示一行摘要 | 状态栏显示"第 n 步" |
| N7 | ChatGPT provider 支持 function calling（Responses API） | 两个 provider 共用同一个工具注册表 |
| N8 | MCP 客户端（stdio）：把外部 MCP server 的工具接进注册表 | 能接一个现成 MCP server 并调用成功 |

N1–N4 是核心，N5–N6 让它可用，N7–N8 可以往后放。

### 要在设计文档里定下来的问题

- 工具结果太长怎么办（截断、只给摘要，还是写临时文件）？
- 多个 tool_use 在同一条响应里：并行还是顺序执行？
- 记忆抽取看完整的工具轨迹，还是只看最后的文本回答？
- 工具输出里出现"忽略之前的指令……"时，怎么在 system prompt 里标明它只是数据？

## 3. Review 分级

规则：**A 级逐行读懂；B 级只审接口和测试；C 级测试通过 + `/code-review` + 自己跑一遍就合并。**
每个改动由 AI 附一段"review 指南"：改了什么、风险在哪、需要细看哪几行。

### A 级：面试会被追问，必须能白板讲清楚

| 模块 | 为什么是 A |
|---|---|
| `agent.py`（agent loop，N2 之后） | agent 的定义本身；终止条件、失败回滚、取消 |
| 工具注册表 + 权限（N3/N4，新） | 安全与可扩展性的取舍 |
| `memory_extract.py` | 抽取 prompt、增删改操作的解析、后台线程、失败不打扰聊天 |
| `memory.py` 的 `recall` / `apply_ops` | 预算、优先级、替换链（`replaces`）、敏感内容拦截 |
| `prompts.py` | system prompt 怎么组装，记忆作为"背景数据"注入 |
| 上下文管理（K 阶段，新） | 压缩策略与 token 成本 |

做法：设计文档自己写，或者逐条拍板；关键函数自己改写一遍或给它加注释，确认真懂。

### B 级：接口要懂，实现扫一眼

| 模块 | 要看的东西 |
|---|---|
| `session.py` | 事件类型、`reply` 的线程与取消模型 |
| `llm.py` / `chatgpt.py` | provider 抽象的签名；重试规则（只重试 502/503/504/529，且发生在任何文本之前） |
| `streaming.py` | 事件流 → content 的契约；N1 之后升为 A |
| `commands.py` | 命令注册与补全的接口 |
| `config.py` | 配置项与环境变量 |

做法：读函数签名和测试名称；确认该测的情况都测了。

### C 级：交给测试和工具

| 模块 | 说明 |
|---|---|
| `cli.py` | 按键、Windows 控制台输入、状态栏 |
| `chatgpt_auth.py` | OAuth、token 加密存储、跨进程续期 |
| `usage.py` | 用量记录 |
| README、`main.py` 参数解析 | 文档与入口 |

做法：测试通过、`/code-review` 无问题、自己手动跑一次。知道它"做了什么"就够了，不需要知道"怎么做的"。

## 4. 面试用架构一页纸（草稿）

> 数字标 `TBD` 的，等 E 阶段评测跑完后填。

**一句话**：Zanbot 是我自己每天用的本地个人 agent，用 Python 从零写，没有用 LangChain 之类的框架。它能多轮对话、自动记住关于我的长期事实，并通过带权限控制的工具调用帮我操作文件和网页。

### 架构

```
          ┌──────────────────────────────────────────┐
 终端前端  │ cli.py: InteractiveTerminal / Plain      │  只负责渲染事件、收集输入
          └───────────────▲──────────────────────────┘
                          │ 事件（TextDelta, ToolCall…, PermissionRequested）
          ┌───────────────┴──────────────────────────┐
 会话层    │ session.py: ChatSession                  │  历史、命令、取消、与 UI 无关
          └──────┬──────────────────────┬────────────┘
                 │                      │ 每轮成功后（后台线程）
          ┌──────▼─────────┐     ┌──────▼──────────────┐
 Agent    │ agent.py loop  │     │ memory_extract.py   │  LLM 判断增/改/删哪些事实
          │ 调用→工具→再调用 │     └──────┬──────────────┘
          └──┬─────────┬───┘            │
             │         │         ┌──────▼──────────────┐
             │   ┌─────▼──────┐  │ memory.py (SQLite)  │  本地存储，召回预算 2000 字
             │   │ 工具注册表  │  └──────┬──────────────┘
             │   │ + 权限检查  │         │ recall
             │   └────────────┘  ┌──────▼──────────────┐
             │                   │ prompts.py          │  system prompt = 规则 + 日期 + 记忆
             │                   └─────────────────────┘
          ┌──▼────────────────────────────────────────┐
 Provider │ llm.py (Anthropic) │ chatgpt.py (Responses)│  流式、重试、错误提示
          └───────────────────────────────────────────┘
```

### 关键设计决策（每条都能展开讲 3 分钟）

1. **成功后才写入。** 失败、取消的轮次不进历史，也不触发记忆抽取。这样重试和取消永远不会留下半截状态。
2. **记忆抽取不走 tool use，而是独立的后台 LLM 调用。** 原因：当时两个 provider 都只支持纯文本；而且放在后台不会拖慢回答。代价：每轮多一次请求，所以支持用 `ZANBOT_MEMORY_MODEL` 换便宜模型。
3. **记忆的可控性优先于"聪明"。** 每次写入都显示 `✓ Remembered #id`，可以 `/forget` 撤销；像密码、key、token 的文本直接拒收；替换操作保留链路（`replaces`），不做静默覆盖。
4. **会话层与 UI 解耦。** `ChatSession` 只发事件，终端只渲染。所以 plain 模式、交互模式、测试共用同一套逻辑；以后加 Web 前端也不用改核心。
5. **只重试安全的错误。** 只对 502/503/504/529 重试一次，因为这些状态码出现在任何文本之前，重试不会重复输出。
6. **工具权限按副作用分级**（N 阶段）。只读工具直接执行；写文件、跑 shell 先问用户；拒绝也作为结果回给模型，让它换办法。
7. **不用 agent 框架。** 为了把 loop、流式解析、取消、权限这些细节掌握在自己手里；整个项目约 3000 行（TBD：N 阶段后更新）。

### 深挖故事（准备 3～4 个）

- **记忆抽取的坑**：模型会把一次性的事（"今天有点累"）当长期事实存下来，或者重复存同一件事。怎么用 kind 分类、有效期（`valid_until`）、候选记忆比对来解决。效果：TBD（精确率/召回率）。
- **流式与取消**：Ctrl+C 在"还没出第一个字"和"正在输出"两种状态下的处理；为什么取消的轮次必须完全不留痕迹。
- **Agent loop 的终止与回滚**（N 阶段后）：最大步数、某一步失败时整轮怎么处理、取消发生在工具执行中间怎么办。
- **Prompt 注入**（S 阶段后）：工具读到的网页里藏着指令时，系统怎么防。

### 我怎么用 AI 写这个项目

我负责设计文档、关键取舍和验收；实现大量由 Claude Code 完成。我把代码分成三级：核心模块（agent loop、记忆、权限）逐行读懂并能改写；接口层只审签名和测试；外围代码（终端按键、OAuth）靠测试和自动 review 把关。这样我的时间花在最需要判断力的地方。
